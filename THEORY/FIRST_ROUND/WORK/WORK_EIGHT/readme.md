## Signal Processing Notes

### Item A — manual 2nd-order coefficients

A 2nd-order **Butterworth** low-pass was chosen (over, say, an ad-hoc RC
cascade) because its analog prototype has a known closed form, which keeps
the "calculate the coefficients ourselves" derivation tractable and
checkable:

1. **Analog prototype** (cutoff `wc` rad/s):

   H(s) = wc² / (s² + √2·wc·s + wc²)

   (`√2` is the 2nd-order Butterworth damping coefficient — the pole angles
   that give a maximally-flat passband.)

2. **Frequency pre-warping**, so the *digital* cutoff lands exactly on `fc`
   after the bilinear transform's frequency warping:

   wc = 2·fs·tan(π·fc/fs)

3. **Bilinear transform**, `s = K·(1 − z⁻¹)/(1 + z⁻¹)`, `K = 2·fs`,
   substituted into `H(s)` and simplified (let `C = K/wc`):

   a₀' = C² + √2·C + 1
   b₀ = b₂ = 1/a₀',  b₁ = 2/a₀'
   a₁ = 2(1 − C²)/a₀',  a₂ = (C² − √2·C + 1)/a₀'  (a₀ = 1)

   giving the difference equation applied by `apply_difference_equation`:

   y[n] = b₀x[n] + b₁x[n−1] + b₂x[n−2] − a₁y[n−1] − a₂y[n−2]

At `fs = 10⁵` Hz (reusing WORK_FIVE's sample rate): `fc=40 Hz` gives
`b ≈ [2.0e-6, 4.0e-6, 2.0e-6]`, `a ≈ [1, -1.9964, 0.9965]`; `fc=100 Hz`
gives `b ≈ [1.0e-5, 2.0e-5, 1.0e-5]`, `a ≈ [1, -1.9911, 0.9912]` (see
`main.py`'s printed output for exact values — both a's poles sit just
inside the unit circle near `z=1`, as expected for a low cutoff relative to
`fs`). `test_biquad_matches_scipy_coefficients` confirms this closed form
reproduces `scipy.signal.butter(2, fc, fs=fs)` bit-for-bit (both are the
same bilinear-transformed Butterworth math — `scipy`'s own design is only
used here as an *independent check*, never in the manual filtering path).
`test_biquad_dc_gain_is_unity` checks `sum(b)/sum(a) == 1` (0 dB at DC, as
required of a low-pass).

### Item B — manual 4th-order coefficients vs. `scipy`

A 4th-order Butterworth factors into **two cascaded 2nd-order sections**
with damping coefficients `d₁ = 2·sin(π/8) ≈ 0.7654` and
`d₂ = 2·sin(3π/8) ≈ 1.8478` (the two conjugate pole-pairs' angles for
N=4). Each section is the same bilinear-transform closed form as item A,
just with `damping` swapped in; the two sections are applied **in series**,
each via its own `for`-loop difference equation (`apply_cascade`) — this is
the "no scipy filter-design/application convenience function" path the
assignment asks for. `test_order4_cascade_matches_scipy_butter_design`
confirms `np.convolve`-combining the two manual sections' `(b, a)`
reproduces `scipy.signal.butter(4, fc, fs=fs)`'s single 4th-order system to
within `1e-8`.

**Matlab equivalent** (not run — no Matlab environment available in this
setup; same "not verified, documented honestly" convention as this repo's
firmware READMEs):

```matlab
% Two cascaded 2nd-order sections, same closed form as coefficients.py:
fc = 100; fs = 1e5;
wc = 2*fs*tan(pi*fc/fs);
d = [2*sin(pi/8), 2*sin(3*pi/8)];
for i = 1:2
    C = (2*fs)/wc;
    a0p = C^2 + d(i)*C + 1;
    b(i,:) = [1 2 1] / a0p;
    a(i,:) = [1, 2*(1-C^2)/a0p, (C^2 - d(i)*C + 1)/a0p];
end
y = filter(b(1,:), a(1,:), x);
y = filter(b(2,:), a(2,:), y);
```

**Comparison result**: running the manual 4th-order cascade and
`scipy.signal.butter(4, ...)` + `scipy.signal.lfilter` on the same
multi-tone test signal (`fc = 100 Hz`, `fs = 10⁵ Hz`) gives
`max|y_manual - y_scipy| ≈ 3.1e-7` (see `main.py`'s printed output,
figure `output/parte_b_comparacion.png`) — on the order of double-precision
floating-point noise accumulated over the two different computational
paths (cascaded biquads vs. `scipy`'s single direct-form-II-transposed
system), not a real disagreement. **Neither is "better" in accuracy** —
they implement the same transfer function and agree to ~7 significant
figures. Where they *would* differ in practice: the cascaded-biquad form
(this manual implementation) is the numerically **more robust** structure
for a hardware/fixed-point or very-low-cutoff-relative-to-fs
implementation, since each 2nd-order stage's coefficients stay well-scaled
and its poles are individually well-conditioned; a single direct-form
4th-order system (as `combine_sections` produces, and what a naive
`scipy.signal.butter(4, ...)` + hand-rolled direct-form loop would use) can
suffer more coefficient-quantization sensitivity at high order. `scipy`'s
own `lfilter` mitigates this internally with a direct-form-II-transposed
implementation, which is why the two still agree closely here in double
precision.
