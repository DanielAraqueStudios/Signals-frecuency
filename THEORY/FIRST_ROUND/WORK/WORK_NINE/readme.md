# AM Modulation Lab

> Part of the [`Signals-frecuency`](../../../../Readme.md) repository — see the root
> README for the full project index.

Implements **Tarea 5**: "modular el audio del gato con frecuencia de 50 kHz
y 500 kHz de frecuencia de muestreo" — amplitude-modulates the cat
(`gato`) recording onto a carrier tone, producing two distinct modulated
outputs at 50 kHz and 500 kHz sample rates, with time-domain and FFT
figures for each.

---

## Scope

Given a message signal (the `gato` recording) and two target sample rates,
this folder resamples the message to each rate, band-limits it, and
amplitude-modulates it onto a shared carrier tone — not just a resample:
the output at each rate is a genuine AM signal (carrier + sidebands), whose
carrier frequency is chosen to stay valid (no aliasing, no DC overlap) at
both 50 kHz and 500 kHz simultaneously.

`modulation_lab.modulation` has **no audio dependencies** — `librosa` is
imported lazily inside `modulation_lab.audio.load_audio` and
`modulation_lab.modulation.modulate_at_rate` (for resampling only), so the
core modulation/filtering functions and their unit tests stay importable
and testable without it installed.

## Usage

```bash
cd WORK_NINE
python main.py
```

Loads `audio_samples/gato/gato.ogg`, then for each target rate (50 kHz,
500 kHz): resamples the recording to that rate, low-pass filters it, AM
modulates it onto the shared 10 kHz carrier, prints the sample count and
min/max, and saves (+ shows) a time-domain/FFT figure to `output/`.

## API Reference

### `modulation_lab.audio`

| Function | Description |
|---|---|
| `load_audio(path)` | Loads a mono file at its native sample rate (lazy `librosa` import) |

### `modulation_lab.modulation`

| Function | Description |
|---|---|
| `lowpass_fft(signal, sample_rate, cutoff_hz)` | Brick-wall FFT low-pass filter |
| `am_modulate(message, sample_rate, carrier_freq_hz, modulation_index)` | `(1 + m·m_norm)·cos(2π·fc·t)` |
| `modulate_at_rate(signal, orig_sample_rate, target_sample_rate, ...)` | Resample → low-pass → AM-modulate, in one call |
| `CARRIER_FREQ_HZ` | Shared carrier frequency (10 000 Hz) |
| `LOWPASS_CUTOFF_HZ` | Message bandwidth cap before modulation (8 000 Hz) |

### `modulation_lab.plotting`

| Function | Description |
|---|---|
| `plot_modulation(signal, sample_rate, title, segment_s=0.01)` | Time-domain segment + single-sided FFT, stacked |

## Signal Processing Notes

- **Carrier choice — `CARRIER_FREQ_HZ = 10 000 Hz`**: the message is
  low-pass filtered to `LOWPASS_CUTOFF_HZ = 8 000 Hz` *before*
  modulation, so the occupied AM band is `[fc − 8 kHz, fc + 8 kHz] =
  [2 kHz, 18 kHz]`. That band:
  - stays above 0 Hz (no overlap with/aliasing into DC — lower sideband
    floor is 2 kHz, well clear of 0), and
  - stays under Nyquist at **both** target rates: 25 kHz Nyquist at
    50 kHz (18 kHz occupied max, comfortable margin) and 250 kHz Nyquist
    at 500 kHz (trivially satisfied).

  Because the same 10 kHz carrier and 8 kHz message bandwidth are valid at
  both rates, `modulate_at_rate` uses one fixed carrier/cutoff pair for
  both outputs rather than needing per-rate tuning.
- **Why low-pass the message at all**: `gato.ogg`'s native sample rate
  (44 100 Hz) allows content up to ~22 kHz, which — undertreated — could
  push the upper sideband (`fc + f_message`) past 25 kHz at the 50 kHz
  target, aliasing back into the modulated signal. `lowpass_fft` removes
  that risk unconditionally rather than relying on the resample step's
  implicit anti-aliasing alone.
- **Standard (not suppressed-carrier) AM**: `am_modulate` uses
  `s[n] = (1 + m·m_norm[n])·cos(2π·fc·n/fs)` with `modulation_index = 1.0`
  by default — the message is peak-normalized to `[-1, 1]` first, so the
  envelope `(1 + m_norm)` never goes negative (no over-modulation), and the
  carrier itself remains visible as a spectral line at `fc`, flanked by
  sidebands at `fc ± f_message` — the structure the tests assert on with a
  synthetic tone.
- **Consistent with `WORK_FIVE`**: `WORK_FIVE/main.py` demonstrates the
  same AM structure — `(2 + sin(2π·60·t))·sin(2π·fc·t)` — and the same
  aliasing concern (its own `fs = 10^5` vs. `fs = 10^6` comparison shows a
  too-low sample rate failing to resolve the AM carrier/sidebands cleanly).
  This folder applies that idea to real audio instead of a synthetic tone.

## Testing

```bash
python -m pytest tests/ -v
```

9 tests:
- `test_modulation.py` (pure functions, synthetic tone standing in for the
  cat audio — no audio file/`librosa` needed): `am_modulate` input
  validation and output length, FFT carrier + upper/lower sideband
  structure at both 50 kHz and 500 kHz, and `lowpass_fft` removing
  above-cutoff content while preserving signal length.
- `test_modulate_at_rate.py` (integration, needs `librosa` + the real
  `gato.ogg`): sample-count correctness at each target rate and carrier
  presence in the modulated spectrum. Skips gracefully via
  `pytest.importorskip`/`pytest.mark.skipif` if `librosa` isn't installed,
  the recording is missing, or the installed audio backend fails to load
  — matching how `WORK_THREE`/`WORK_FOUR` keep real-audio I/O out of the
  required unit-test path.
