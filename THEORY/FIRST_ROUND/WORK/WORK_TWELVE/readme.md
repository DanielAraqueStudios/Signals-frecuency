# NLMS Adaptive Filter Lab

> Part of the [`Signals-frecuency`](../../../../Readme.md) repository — see the root
> README for the full project index.

Implements the Normalized Least Mean Squares (NLMS) adaptive filter from
scratch (plain NumPy, no library adaptive-filter call) and exercises it on
three tasks: FIR system identification, adaptive noise cancellation, and a
direct comparison against plain LMS on an input with non-stationary power.

## Signal Processing Notes

- **NLMS update rule (task 1)**: implemented directly as
  `w[n+1] = w[n] + (mu / (eps + ||x_n||^2)) * e[n] * x_n` in
  `adaptive.nlms_filter` — i.e. plain LMS with the step size divided by the
  input window's instantaneous energy `||x_n||^2`, plus `eps` to avoid
  dividing by (near-)zero when the input momentarily goes quiet. Driving an
  unknown 5-tap FIR system (`[0.8, -0.4, 0.25, -0.1, 0.05]`) with white
  noise and adapting a same-length NLMS filter against its output drives
  the weight error from `≈0.94` at initialization to effectively `0`
  (`t1_system_identification.png`), with the adapted taps visibly settling
  onto the true coefficients (dashed lines) within a few hundred samples.
- **Adaptive noise cancellation (task 2)**: NLMS is given the noisy
  observation as input and the *clean* reference as the desired signal it
  must predict — this only works here because the clean reference is
  available during training (a standard simplification for this kind of
  classroom ANC demo; a true single-microphone denoiser would instead use
  a second noise-only reference channel). For both the 60 Hz tone
  (`t2_noise_cancellation_tone.png`) and the cat recording
  (`t2_noise_cancellation_cat.png`), the steady-state RMS error between the
  recovered signal and the clean reference drops well below the RMS error
  between the raw noisy observation and the clean reference (the tone case
  drops from `std ≈ 0.50` to `std ≈ 0.16` in `main.py`'s printed summary),
  confirming the filter is doing real denoising rather than just passing
  the input through.
- **NLMS vs. plain LMS under non-stationary power (task 3) — the key
  practical point of this lab**: `varying_power_signal` builds a white-noise
  input whose amplitude steps from `0.05` to `2.0` halfway through (a
  40x jump in standard deviation, 1600x in power). Both filters are driven
  through the *same* unknown-FIR system-identification task from task 1 on
  this input. Plain LMS uses one fixed `mu`; NLMS's effective step size is
  `mu / (eps + ||x_n||^2)`, which *shrinks automatically* when `||x_n||^2`
  is large and *grows automatically* when it is small. This means NLMS's
  effective step size self-scales with the input's instantaneous power,
  while LMS's does not. Concretely:
  - A `mu` for plain LMS chosen to be numerically stable during the
    high-power second half (`mu = 0.05` here; LMS is well known to diverge
    once `mu * E[x^2]` exceeds roughly 2, so `mu` must be kept small enough
    for the *loudest* segment the filter will ever see) is far smaller than
    the step size that would converge quickly during the low-power first
    half. The result, measured in `test_nlms_converges_more_consistently_than_lms_under_varying_power`
    and printed by `main.py`, is that LMS's low-power-segment steady-state
    RMS error (`≈0.040`) is roughly **34x larger** than NLMS's
    (`≈0.0012`) under the same `mu`/`mu`-analog and the same signal — LMS
    is simply too sluggish at low power once it has been detuned for
    safety at high power.
  - NLMS does not have to make that trade-off: because its denominator
    `||x_n||^2` tracks the input's own instantaneous scale, the *ratio*
    between its low-power and high-power steady-state error stays much
    closer to 1 than LMS's equivalent ratio (asserted directly in the test
    above, and visible in `t3_nlms_vs_lms_varying_power.png` as the NLMS
    error trace sitting at a comparable floor on both sides of the power
    step, while the LMS error trace is visibly worse — closer to the
    noise floor it never fully adapts out of — on the low-power side).
  - This is the standard practical argument for preferring NLMS over plain
    LMS whenever the input signal's power is not known in advance or
    varies over time (e.g. speech, which alternates between silence and
    loud voiced segments): LMS requires re-tuning `mu` to the expected
    signal power and is only safe for the worst case it must tolerate,
    whereas NLMS's step size is self-tuning by construction.

## Testing

```bash
python -m pytest tests/ -v
```

8 tests cover:
- `adaptive.nlms_filter`: the adapted weights converge to a known unknown
  FIR system's coefficients within numeric tolerance; the weight-error norm
  shrinks by more than 100x from initialization to the end of training; the
  prediction-error energy in the last quarter of training is more than 100x
  smaller than in the first quarter; NLMS recovers a clean 60 Hz tone from a
  noisy observation with less than half the noisy observation's RMS error.
- `test_nlms_converges_more_consistently_than_lms_under_varying_power`: on
  the same varying-power input and the same system-identification task,
  NLMS's low-power/high-power steady-state error *ratio* is measurably
  smaller than plain LMS's equivalent ratio under a `mu` chosen to be
  stable at high power — the quantitative form of this lab's central claim.
- `signals`: `tone_signal` matches its closed-form definition;
  `sample_times` produces the expected length and range;
  `varying_power_signal` actually produces a large variance jump between
  its two halves.
