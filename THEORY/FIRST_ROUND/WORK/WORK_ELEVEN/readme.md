# LMS Adaptive Filter Lab

> Part of the [`Signals-frecuency`](../../../../Readme.md) repository — see the root
> README for the full project index.

Implements the LMS (Least Mean Squares) adaptive filter from scratch (plain
NumPy, no library adaptive-filter call): the update rule
`w[n+1] = w[n] + mu * e[n] * x[n]`, with `e[n] = d[n] - y[n]` the error
between a desired/reference signal and the filter's output. Demonstrated on
system identification, adaptive noise cancellation, and a step-size (`mu`)
convergence sweep.

## Signal Processing Notes

- **The LMS update rule (all tasks)**: `run_lms` keeps a tap-delay line
  `x_vec[n]` of the last `n_taps` input samples, computes
  `y[n] = w[n] . x_vec[n]`, the instantaneous error
  `e[n] = d[n] - y[n]`, and then nudges every tap in the direction that
  reduces that sample's squared error:
  `w[n+1] = w[n] + mu * e[n] * x_vec[n]`. This is stochastic gradient
  descent on the mean-squared error surface `E[e[n]^2]`, using the
  *instantaneous* squared error as a (noisy) stand-in for its expectation —
  the "least mean squares" in the name refers to that expectation, which
  LMS never computes exactly, only approaches on average over many samples.
- **System identification (task 1)**: feeding LMS a white-noise input `x`
  and the unknown filter's output `d = h_true * x` makes the problem
  well-posed — white noise excites every tap equally, so the weight vector
  has a unique minimum at `w = h_true` (zero error). `t1_weight_convergence.png`
  shows every one of the 5 adaptive taps converging onto its corresponding
  dashed target line; `main.py`'s printed `||w_final - h_true||` reaches
  ~0 within `mu = 0.02` and ~4000 samples, and `tests/test_lms.py` checks
  this numerically: final weight error is required to be under `0.05` and
  under `5%` of the initial weight error.
- **Adaptive noise cancellation (tasks 2, 2b)**: the classic two-input ANC
  setup is reproduced — a *primary* input (`noisy_tone` / `noisy_cat`)
  carries the signal of interest plus noise, and a separate *reference*
  input (`noise_source`) is correlated with that noise (through a fixed,
  unknown-to-LMS coupling filter) but uncorrelated with the signal of
  interest. LMS adapts a filter on the reference input to predict the noise
  component of the primary input; the filter's *output* `y[n]` is its best
  estimate of the noise, so the *error* `e[n] = primary[n] - y[n]` is the
  noise-cancelled signal (this is why `main.py` keeps `e`, not `y`, as the
  recovered signal). `t2_noise_cancellation_tone.png` shows the 60 Hz tone
  recovering a clean sinusoid from a visibly noisy trace; the residual
  standard deviation against the true clean tone drops from ~0.62 to ~0.14
  (steady-state half of the run) — not perfect cancellation, since the
  noise reference only reaches the primary input through a causal FIR path
  LMS has to learn from a short run, but a clear, measurable improvement.
  `t2b_noise_cancellation_cat.png` repeats the same scheme on the cat audio.
- **Convergence vs. step size mu (task 3)**: `mu` trades convergence speed
  against both residual error and stability. The precise stability
  condition for LMS is `0 < mu < 2 / lambda_max`, where `lambda_max` is the
  largest eigenvalue of the input signal's autocorrelation matrix `R`; in
  practice, for a white-noise input of power `sigma_x^2` and `n_taps`
  weights, `R`'s eigenvalues are all approximately `sigma_x^2`
  (white noise decorrelates immediately, so `R` is close to `sigma_x^2 * I`),
  which gives the simpler practical bound
  `mu < 2 / (n_taps * sigma_x^2)` (safely under `2 / trace(R)`, a common
  rule of thumb since `trace(R) = n_taps * sigma_x^2` for this input).
  For task 1's setup (`n_taps = 5`, `sigma_x^2 = 1`) that bound sits around
  `mu < 0.4`. `t3_mu_sweep.png` and the printed final-MSE table confirm all
  three regimes: at `mu = 0.001` the learning curve descends but is still
  well above the noise floor after 4000 samples (too slow to fully settle);
  at `mu = 0.01`-`0.1` the curve drops to machine-precision MSE within a few
  hundred samples (fast, stable convergence, each step small enough that
  the weight-error update is a contraction); at `mu = 0.5` (above the ~0.4
  bound) the weights overshoot further on every update than they correct,
  the error feeds back into an ever-larger step, and the recursion diverges
  to `inf` (`tests/test_mu_convergence.py` checks exactly this ordering:
  small `mu` leaves more residual weight error than moderate `mu`, and an
  excessive `mu` blows up).

## Testing

```bash
python -m pytest tests/ -v
```

9 tests cover:
- `lms.run_lms`: output/error array shapes and the `e = d - y` identity;
  an all-zero input/desired pair leaves the weights at zero.
- System identification: LMS recovers the unknown FIR coefficients within a
  tight numeric tolerance, and the final weight error is far smaller than
  the initial weight error.
- `unknown_system.apply_unknown_system`: matches the convolution definition
  (an impulse input returns the filter's own coefficients) and preserves
  signal length.
- `signals`: `tone_signal` matches its closed-form definition; `white_noise`
  matches its requested variance and zero mean over a long run.
- Step-size sweep: a small `mu` leaves more residual weight error after a
  fixed number of samples than a moderate `mu`; a `mu` well past the
  `2 / (n_taps * sigma_x^2)` stability bound diverges.
