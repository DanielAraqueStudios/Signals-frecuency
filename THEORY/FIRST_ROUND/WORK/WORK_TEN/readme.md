## Signal Processing Notes

- **Long 60 Hz signal (task 6)**: reuses `WORK_FIVE`'s tone,
  `sin(2*pi*60*t)` at `fs = 10**5` Hz, but extended from WORK_FIVE's 0.05 s
  default to **1.0 s** so it qualifies as a "long signal" and gives a
  well-resolved FFT (1 Hz bin spacing) around the 60 Hz peak.
- **Removing the negative part (tasks 6, 6.1)**: implemented explicitly in
  `spectrum.remove_negative_frequencies` — FFT the signal, zero every bin
  at a negative frequency, inverse-FFT back to the time domain. This is
  literally the first step of building the analytic signal (and what
  `scipy.signal.hilbert` does internally), but is done by hand via
  `numpy.fft` here per the assignment's explicit instruction, rather than
  calling `scipy.signal.hilbert` for this sub-step. `scipy.signal.hilbert`
  is used only in `hilbert_tools.py`, for tasks 6.2/6.3, where the
  assignment names "transformada de Hilbert" directly.
- **Self-contained AM cat audio (task 6.1)**: `WORK_NINE` is building a
  separate AM-modulation exercise on the same cat audio concurrently. To
  keep this folder self-contained and avoid depending on unfinished work,
  `main.py` loads its own copy of `WORK_THREE/audio_samples/gato/gato.ogg`
  (into `WORK_TEN/audio_samples/gato/`) and AM-modulates it locally via
  `fir_iir_lab.signals.am_modulate`, using the same
  `message * sin(2*pi*f_c*t)` scheme as `WORK_FIVE/am_lab.modulated_signal`'s
  carrier term, at a 20 kHz carrier (comfortably above the audio band and
  below the cat recording's Nyquist rate) — standing in for "the modulated
  gato audio from Tarea 5" as the assignment's cross-reference intends.
  Only the first 2 s of the recording are processed, to keep the FFTs and
  filters fast; nothing stops running the same functions on the full file.
- **FIR vs. IIR (tasks 6, 6.1)**: `design_fir_lowpass` (window-method,
  `scipy.signal.firwin`) and `design_iir_lowpass` (`scipy.signal.butter`)
  are both applied zero-phase via `scipy.signal.filtfilt`, so neither
  introduces phase delay in the comparison plots — differences visible in
  `t6_fir_iir_300hz.png`/`t6_1_fir_iir_10khz_cat.png` are due to filter
  *shape* (transition-band sharpness, ripple), not phase.
- **Filter order ≥ 10 (task 6.4)**: `t6_4_order_sweep.png` compares the
  300 Hz FIR filter at orders 2, 10, 20, 50, 100. As order increases:
  - The **transition band narrows** — the passband/stopband edges get
    sharper in the frequency-domain plot, visibly cutting off closer to
    exactly 300 Hz at order 100 than at order 2.
  - **Group delay increases** — a higher-order FIR filter has more taps,
    so (even though `filtfilt` cancels net phase distortion by filtering
    forward and backward) the filter needs proportionally more samples of
    "runway" at each edge before its output settles, visible as a longer
    transient at the start of the time-domain trace for higher orders.
  - **Ringing/overshoot near discontinuities** grows slightly with order
    for a windowed-sinc (Gibbs-like) filter, though `firwin`'s default
    Hamming window keeps this modest compared to a naive rectangular
    truncation.
  - FIR filters (unlike IIR) stay **numerically stable at any order**
    tested here — an IIR Butterworth filter's coefficients, by contrast,
    become poorly conditioned at high orders and can produce unstable or
    numerically inaccurate results well before order 100; this is a
    structural reason FIR is often preferred when a very sharp cutoff is
    needed and phase/stability matter more than computational cost.

## Testing

```bash
python -m pytest tests/ -v
```

10 tests cover:
- `spectrum.remove_negative_frequencies`: negative FFT bins are actually
  zeroed, and the resulting analytic signal reconstructs a synthetic
  tone's expected (halved) constant envelope.
- `spectrum.single_sided_fft`: peak frequency matches a known tone.
- `filters`: FIR and IIR lowpass filters attenuate a stopband test tone
  relative to a passband tone by >10x; the FIR filter passes a passband
  tone through largely unattenuated.
- `hilbert_tools.hilbert_envelope`: recovers a known slow envelope from a
  synthetic AM test signal, and returns a constant envelope for a pure tone.
- `signals`: `am_modulate`/`tone_signal` match their closed-form definitions.
