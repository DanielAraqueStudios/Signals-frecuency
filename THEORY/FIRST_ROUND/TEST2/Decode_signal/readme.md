# 16-Level AM ASCII Decoder (Decode_signal, TEST2)

> Part of the [`Signals-frecuency`](../../../../Readme.md) repository — see the root
> README for the full project index.

Decodes the ASCII text embedded in `PUNTO_3/Muestras/Muestra*.csv`, per the
signal format supplied for this exercise:

- 1000 Hz carrier, amplitude-modulated with 16 discrete levels (0..15).
- Each symbol lasts 15 ms.
- The first 240 ms (16 symbols) is a calibration ramp: levels 0,1,2,...,15.
- After that: data, 2 nibbles (symbols) per character, high nibble first.
- Terminated by a `0x00` byte.

None of these parameters (carrier, level count, symbol duration, ramp,
terminator) were guessed or inferred — they were given directly for this
exercise. The sample rate, however, **is** recovered from each file's own
timestamps (not assumed), since it differs between files.

## Scope

Decode the ASCII message hidden in each `Muestra*.csv` in
`../PUNTO_3/Muestras/`, using the amplitude-shift-keying-like scheme
described above (16-level AM = 4 bits/symbol, 2 symbols/byte).

## API Reference

### `decode_lab.data`

| Function | Description |
|---|---|
| `load_signal(csv_path)` | Reads `tiempo,amplitud` CSV via `np.loadtxt` (fast — some files are 60,000+ rows and `np.genfromtxt` was slow enough to look like a hang), returns `(t, amplitude, sample_rate_hz)` — `sample_rate_hz` from the median of real timestamp deltas |

### `decode_lab.envelope`

Pipeline order, per the assignment's own instruction: **(1)** FFT to
measure the real carrier, **(2)** Hilbert transform of the raw signal for
the envelope, **(3)** derive the lowpass cutoff from the measured carrier.

| Function | Description |
|---|---|
| `measure_carrier_hz(amplitude, sample_rate)` | Step 1: FFT magnitude peak within ±100 Hz of the nominal 1000 Hz carrier |
| `choose_cutoff_hz(carrier_hz, symbol_rate_hz)` | Step 3: `min(4 * symbol_rate, 0.3 * carrier)` — stays above the 66.7 Hz symbol rate and below the measured carrier |
| `am_envelope(amplitude, sample_rate)` | Steps 1-3 wired together: `\|hilbert(amplitude)\|`, lowpass-filtered at the derived cutoff. Returns `(envelope, carrier_hz, cutoff_hz)` |

### `decode_lab.symbols`

| Function | Description |
|---|---|
| `symbol_averages(envelope, sample_rate, trim_fraction=0.2)` | Mean of each 15 ms window, trimming 20% off each edge to avoid inter-symbol transition artifacts |
| `calibrate(symbol_avgs)` | Least-squares fit of `level = slope*avg + intercept` from the first 16 (known 0..15) symbols; returns `(slope, intercept, residuals)` |
| `levels_from_data_symbols(symbol_avgs, slope, intercept)` | Applies the fit to the symbols after the ramp, rounds and clips to `[0, 15]` |

### `decode_lab.decode`

| Function | Description |
|---|---|
| `levels_to_bytes(levels)` | Pairs `(high_nibble, low_nibble)` into bytes; stops at the first `0x00`; returns `(bytes, terminator_found)` |
| `bytes_to_text(byte_values)` | Renders printable bytes as characters, others as `\xNN` — never silently drops or guesses |
| `group_with_dashes(text, block_size=6)` | Inserts a dash every `block_size` characters, for display only — see "The dash question" below |

### `decode_lab.pipeline`

| Function | Description |
|---|---|
| `decode_csv(csv_path)` | End-to-end: loads, demodulates, calibrates, decodes; returns a `DecodeResult` dataclass with every intermediate value |

Every file decodes to exactly 30 printable ASCII bytes (letters and
digits), with a maximum calibration residual around 0.43 levels (well
under the 0.5 needed for correct rounding) — a strong, repeatable success
across all 13 independently-captured files, not a fluke on one. Note the
measured carrier is close to but not exactly 1000 Hz, and drifts between
files (999.96 Hz for Muestra01, ~1066-1100 Hz for the rest) — this is why
`measure_carrier_hz` exists rather than assuming a fixed value (see
"A detour: bandpass denoising" below for what went wrong when that
assumption was hardcoded).

### The dash question

30 characters split into exactly 5 blocks of 6 gives a natural
license-key-style display: `XLmtZh-X0r0RK-...`. Whether that dash is
literally part of the encoded bitstream, or purely a display convention,
was investigated directly: byte `0x2D` (`-`) was searched for across all 6
whole-symbol offsets, both nibble orders, and a full sub-symbol timing
sweep (every ~0.15 ms across one 15 ms symbol) on Muestra01 — it never
appears, under any of those variations, and the decode is unchanged by
denoising. `group_with_dashes` therefore inserts the dash as a **display
formatting step after decoding**, not as something decoded from the
signal. If the dash is meant to be part of the actual bitstream, the
encoding scheme differs from the nibble-pair-to-ASCII one specified for
this exercise (a different symbol alphabet, most likely), and would need
to be given explicitly to decode correctly.

### A detour: bandpass denoising (and why it's not in the pipeline)

An earlier version added an optional bandpass filter around a hardcoded
1000 Hz carrier before the Hilbert transform, meant purely as denoising.
On Muestra01 it worked (residual dropped from 0.43 to 0.03, same decoded
bytes) — but applied to the other 12 files, whose real carriers measured
60-100 Hz away from 1000 Hz, the fixed-frequency bandpass clipped the
actual carrier out entirely and produced garbage. Switching to a
numerically stable SOS filter didn't fix it; measuring the carrier per
file (rather than assuming 1000 Hz) for the bandpass *did* fix the
garbage, but the approach was still fragile enough that it was dropped
from the default pipeline. The FFT carrier measurement was kept, but
repurposed for what the exercise actually asked for: choosing the
envelope-smoothing cutoff frequency, not pre-filtering the raw signal.

## Signal Processing Notes

- **Sample rate differs per file** (53.7 kHz to 99.3 kHz) despite every
  file having exactly 76 total symbols and the same 15 ms/symbol duration
  — confirmed by recomputing `sample_rate_hz` from each file's own
  timestamps rather than assuming one value.
- **No terminator (`0x00`) was ever reached** in any of the 13 files —
  each ends exactly at symbol 76 (16 calibration + 60 data = 30 bytes)
  with no room for one more nibble pair. `terminator_found` is reported as
  `False` for all 13 rather than silently assumed `True`; either the
  capture window was sized to stop right at 30 bytes by design, or the
  terminator falls just past what was captured.
- **Calibration, not a fixed threshold, drives the level mapping.** The
  16-symbol ramp is fit with ordinary least squares per file (residuals
  ~0.43 levels), which self-corrects for each file's own DC offset/gain
  rather than assuming a shared absolute amplitude scale — necessary since
  raw envelope amplitudes vary noticeably between files even before
  decoding starts.
- **Envelope smoothing cutoff is derived, not hardcoded**: `choose_cutoff_hz`
  takes `min(4 * symbol_rate, 0.3 * measured_carrier)`, which lands at
  266.67 Hz for every file in this dataset (since `4*66.7=266.8` is the
  binding constraint at both the ~1000 Hz and ~1066-1100 Hz carriers
  measured) — sitting well above the ~66.7 Hz symbol rate (so symbol
  transitions survive) and well below the carrier (so carrier ripple is
  removed), the same above-message/below-carrier logic used in
  `../PUNTO_1/` and `../PUNTO_2/`.
- **Trimming 20% off each symbol window's edges** before averaging avoids
  the brief amplitude transition between adjacent symbols contaminating
  the estimate — without this, calibration residuals were visibly worse
  in early testing on `Muestra01.csv`.
- **CSV loading uses `np.loadtxt`, not `np.genfromtxt`.** `genfromtxt`
  sniffs each line's dtype individually and was slow enough on these
  60,000+ row files to look like `main.py` had hung; `loadtxt` (no dtype
  guessing needed — every column is a plain float) loads the same file in
  well under a second.

## Testing

```bash
python -m pytest tests/ -v
```

14 tests: FFT carrier measurement on a known synthetic tone;
`choose_cutoff_hz` staying between the symbol rate and the carrier;
`am_envelope`'s full step-1/2/3 pipeline on a synthetic constant-amplitude
carrier; the calibration least-squares fit on both noiseless and noisy
synthetic ramps; level rounding/clipping at the valid-range boundaries;
nibble-pair-to-byte decoding including terminator detection (both found
and correctly-reported-missing cases); byte-to-text rendering for both
printable and non-printable bytes; `group_with_dashes` on exact, remainder,
and empty inputs; and, most importantly,
`test_pipeline_roundtrip.py::test_known_string_round_trip`, which builds a
synthetic 16-level AM signal end-to-end for a known message (`"Hi!"`),
runs the *entire* real pipeline (FFT carrier measurement, Hilbert envelope,
cutoff selection, symbol averaging, calibration, decoding) against it, and
asserts the exact original string is recovered — proving pipeline
correctness independently of the real, noisier CSV files.
