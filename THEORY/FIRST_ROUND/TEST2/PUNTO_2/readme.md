# Bitstream Decoding Lab (Punto 2)

> Part of the [`Signals-frecuency`](../../../../Readme.md) repository — see the root
> README for the full project index.

Decodes the ASCII message hidden in an OOK/ASK-modulated bit signal
(`muestras/01_2_modulated_signal_10.0_100.0_1.0.csv`): FIR/IIR filtering at
the bit rate (and why it fails), Hilbert-envelope bit reconstruction, and
bits-to-ASCII decoding.

## Signal Processing Notes

**Data verification.** The CSV has 14 400 samples with `dt = 1e-5 s` exactly
(measured from the timestamps, not assumed from the filename), confirming
`fs = 100 kHz`. Total duration is 0.14399 s. With `T = 1 ms` per bit this
gives 144 bits = 18 bytes, matching an 18-character ASCII message.

**(a) Why FIR order 50 / IIR order < 10 at the bit frequency (1/T = 1 kHz)
fails to reveal the square bit pattern.** The OOK (on/off keying) signal is
`envelope(t) * sin(2*pi*f_c*t)` with `f_c = 10 kHz`. Its real spectral
energy sits around the 10 kHz carrier, with sidebands spaced by the keying
rate — not at 1 kHz itself, which for this signal is essentially empty
spectrum (near-DC/noise floor). A lowpass filter with a 1 kHz cutoff applied
directly to the *raw, carrier-modulated* signal therefore does not recover
the bit envelope: it just suppresses the carrier and passes whatever small
low-frequency content exists, leaving a near-flat/noisy trace instead of a
clean square wave. This is confirmed by `t2a_spectrum.png` (FFT shows the
energy concentrated near 10 kHz, not 1 kHz) and by `t2a_filtered_bit_rate.png`
(both FIR and IIR outputs at 1 kHz are near-empty, not square). Recovering
the bit envelope instead requires *demodulating* the carrier first (e.g. via
the Hilbert transform, part (b)) before any lowpass filtering at the bit
rate makes sense.

**(b) Hilbert envelope + square-wave reconstruction.** `hilbert_envelope`
gives the analytic-signal magnitude, i.e. the on/off amplitude envelope of
the OOK signal. This envelope is then lowpass-filtered at `0.3 * (1/T)` to
smooth out carrier ripple while preserving bit transitions. For each 1 ms
bit window, the smoothed envelope is averaged, and the 144 per-bit averages
are split into two clusters (high/low amplitude) via a 1-D 2-means pass; the
midpoint between the converged cluster centroids is used as the decision
threshold. This self-calibrates to the signal's actual high/low levels
instead of assuming a fixed absolute amplitude. See `t2b_hilbert_bits.png`
for the three stacked panels (raw signal, Hilbert magnitude, reconstructed
square wave).

**(c) Decoded message.** Grouping the 144 recovered bits into 18 bytes,
8 bits/byte, MSB-first, **starting at bit offset 0** (no leading junk bits)
gives 18/18 printable ASCII bytes — the unique best-scoring combination
across all 8 offsets x {MSB-first, LSB-first} (16 candidates checked; every
other combination scored far lower on printable-ASCII count). The decoded
message is:

> **`El Rey Leon (1994)`**

## Testing

```bash
python -m pytest tests/ -v
```

- `tests/test_roundtrip.py::test_known_string_round_trip` — the critical
  correctness test: builds a synthetic OOK signal for a known short string
  (`"Hi DSP!"`), runs the full envelope -> smoothing -> per-bit threshold ->
  ASCII pipeline, and asserts the exact known string is recovered
  (offset 0, MSB-first).
- `tests/test_roundtrip.py::test_square_wave_matches_bits` — checks
  `square_wave_from_bits` expansion.
- `tests/test_decode.py` — unit tests for the bits<->ASCII byte-packing
  helpers and for `best_ascii_decoding`'s offset search on a longer known
  string.

All 5 tests pass; `main.py` runs against the real CSV without error and
prints the decoded message above.
