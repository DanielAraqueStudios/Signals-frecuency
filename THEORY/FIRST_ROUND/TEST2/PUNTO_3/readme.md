## Usage

```bash
cd PUNTO_3
python main.py
```

Loads the real image at `IMAGE_PATH` (top of `main.py`, default
`../muestras/imagen.jpg`) as grayscale; if it is missing, falls back to the
synthetic generator (`generar_imagen_sintetica`, kept as demo/fallback and
used by the tests). Then applies `kernel_pasa_bajas`,
`kernel_pasa_altas00`, `kernel_pasa_altas02`, the lowpass-then-highpass
cascade, and the new zero-sum kernel, printing each kernel's real numeric
sum and saving all six images to `output/`.

## Signal Processing Notes

**What the code does**: loads/grayscales an image and applies discrete 2D
convolution with three fixed 5x5 kernels — an all-positive, sum-to-1
averaging kernel (`kernel_pasa_bajas`, a 2D moving-average / blur, same idea
as the 1D moving-average filters in
[`WORK_FOUR`](../../WORK/WORK_FOUR/readme.md)) and two kernels with a
strong positive center against a negative surround
(`kernel_pasa_altas00`, `kernel_pasa_altas02`, edge/detail-emphasizing,
Laplacian-of-Gaussian-shaped), then a lowpass-then-highpass cascade
("Filtro Pasa Bandas").

### (a) Is this a filter?

**Yes.** Convolution with a fixed kernel is, by definition, a linear,
shift-invariant (LSI) filter — the 2D, spatial-domain analogue of 1D FIR
filtering: `y[m,n] = sum_i sum_j h[i,j] * x[m-i, n-j]`, same operation as
1D convolution, just over two independent axes instead of one. Each kernel
here is a small, finite-support impulse response, exactly like an FIR tap
vector. Concretely:

- `kernel_pasa_bajas` (sum = 1.0, all positive) is a literal 2D moving
  average — a spatial lowpass filter that smooths/blurs, attenuating high
  spatial frequencies (edges, fine texture) while preserving the local
  average brightness (DC gain 1).
- `kernel_pasa_altas00` and `kernel_pasa_altas02` (strong positive center,
  negative surround) behave like a discrete Laplacian / high-boost filter:
  they respond strongly where brightness changes quickly (edges) and weakly
  where it doesn't (flat regions) — a spatial highpass.
- The cascade applies lowpass then highpass in sequence, i.e. a bandpass:
  it removes both the lowest spatial frequencies the highpass stage would
  otherwise re-amplify from noise and the highest frequencies the blur
  already removed.

### (b) New square, zero-sum kernel

`kernel_nuevo_suma_cero` (3x3, `image_filter_lab/kernels.py`):

```
[[ 1,  1,  1],
 [ 1, -8,  1],
 [ 1,  1,  1]]
```

Sum verified numerically as exactly `0.0` (`tests/test_kernels.py::test_kernel_nuevo_suma_cero_is_zero`,
and printed by `main.py`) — the classic discrete Laplacian.

**What actually happens**, checked on synthetic patterns (and on a
controlled flat 32x32 patch, `tests/test_filtering.py`):

- A **sum-zero kernel has no DC gain**: on a uniform 128-gray region its
  `filter2D` output is exactly `0` everywhere in the interior (verified:
  `interior.min() == interior.max() == 0`). Flat regions carry no
  brightness information through the filter at all, regardless of how
  bright they were.
- On a **hard edge**, the same kernel produces a large, non-trivial
  response (`|output| > 20` right at the transition; verified in
  `test_kernel_nuevo_edge_nontrivial`) — it becomes a pure
  edge/derivative detector.
- **Compared against the (a) kernels on the same flat 32x32 region**
  (their *actual* computed sums, not assumed):
  - `kernel_pasa_altas00` — real sum **1.0** (not zero, contrary to its
    "pasa altas" name suggesting a pure highpass) — on the flat region its
    `filter2D` output is `128` everywhere (`= gray_value * sum`), i.e. it
    still passes a DC component through, because its sum isn't zero.
  - `kernel_pasa_altas02` — real sum **0.0** — on the same flat region its
    output is `0` everywhere, just like the new kernel: it already had no
    DC gain despite not looking "obviously" zero-sum from its coefficients.
  - `kernel_nuevo_suma_cero` — sum `0.0` — output `0` on the flat region,
    matching `kernel_pasa_altas02`'s behavior.

So changing a kernel's values while keeping the sum at zero doesn't change
*whether* flat regions vanish (they always do, for any zero-sum kernel) —
it changes *how strongly and in what pattern* edges/transitions respond,
since only the zero-sum property, not the specific coefficients, controls
the DC rejection.

### Observed on the real photo (`muestras/imagen.jpg`)

The photo is a yellow debit card on a dark wood-grain desk (converted to
grayscale). Observations from the saved `output/` figures. `cv2.filter2D`
on uint8 saturates, so negative responses clip to 0 and highpass outputs
look mostly black with bright lines at edges.

- **`01_pasa_bajas`**: a mild blur; the card's fine details (chip contacts,
  "débito" text, contactless symbol) soften, and the wood-grain streaks
  smooth out, while overall brightness is unchanged (sum = 1).
- **`02_pasa_altas00`** (sum = 1.0): keeps the image's brightness (card
  stays light, desk stays dark) and adds a strong outline and grain
  texture on top: card border, logo, text and chip edges are sharpened,
  and the wood grain is amplified.
- **`03_pasa_altas02`** (sum = 0): the card interior and the flat desk areas
  go near black; only edges remain (card outline, "Ba" letters, chip,
  Mastercard circles, arcs). The wood grain and the noisy speculars on the
  desk's top-left still leave a faint speckle, because grain is genuine
  fine-scale detail, not a flat region.
- **`04_pasa_bandas`** (blur then `altas02`): same edge-only look but
  cleaner and dimmer; the blur suppressed part of the grain/noise before
  the highpass stage.
- **`05_kernel_nuevo`** (3x3 zero-sum Laplacian): also flattens the card
  face and desk to black and outlines the same edges, but weaker than
  `altas02` (center weight -8 vs. 24, smaller support), so the output is
  darker overall with thin, faint edge lines.

## Testing

```bash
python -m pytest tests/ -v
```

12 tests cover: the synthetic-image generator's shape/dtype/value-range and
that its flat vs. checkerboard quadrants actually differ in local variance;
each of the four kernels' real numeric sum and squareness;
`filter2D`/cascade output shape matching input shape; and the new kernel's
near-zero response on a flat region vs. its strong response on a hard edge.
